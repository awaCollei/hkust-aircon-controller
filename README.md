## 🥵 为什么会有这个项目？

如果你住在HKUST宿舍，你一定经历过这些：

### 只能开，不能"开一会关一会"

空调开关只有一个按钮——按一下开，再按一下关。想让它自动开半小时再关半小时？不存在的。你只能：
- 开着→睡着→冻醒→关掉→热醒→再开...
- 或者干脆调低制冷强度一直开着，第二天看着电费账单流泪

### 定时功能？约等于没有

官方确实有个"Power-off after"，但……

**什么叫关闭时间只能设置在今天？！**

就是如果你想明天凌晨4点关，对不起，办不到。因为这个定时器只能选"今天"的某个时间，而凌晨4点已经属于"明天"了。

所以晚上22点想睡觉的人，只能设置22:00-23:59之间的某个时间关。那凌晨2点被热醒了怎么办？爬起来再开一次呗……

### 真的贵

开着空调一小时1块多。一晚上8小时就是10块钱，一个月就是300块……要不我还是睡common room蹭空调吧

## 🎯 项目功能

### 核心功能

1. **🔑 Token身份验证**
   - 输入你的Bearer Token即可连接空调系统
   - 无需每次输入用户名密码

2. **📊 实时状态监控**
   - 设备名称 & 状态（开启/关闭）
   - 电压、电流、功率、功率因数
   - 实时更新时间

3. **🎮 手动控制**
   - 开启/关闭

4. **⏰ 智能定时（重点！）**

   | 模式 | 说明 | 使用场景 |
   |------|------|----------|
   | **单次定时** | 设定X分钟后开启/关闭（只执行一次） | 睡前定时关闭，避免整夜开空调 |
   | **循环模式** | 开X分钟 → 关Y分钟 → 循环往复 | 省电模式：开30分钟关30分钟，既凉快又省钱 |

### 特色功能

- 🌐 **美观的Web界面**：手机/电脑都可访问，响应式设计
- 📝 **操作日志**：所有操作都有记录，方便排查
- 🔄 **自动刷新**：每30秒自动更新状态

## 📦 安装与使用

### 1. 克隆项目

```bash
git clone https://github.com/awaCollei/hkust-aircon-controller.git
cd hkust-aircon-controller
```

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

### 3. 获取你的Token

> 仅供学习参考，请勿在真实环境操作

1. 打开浏览器，登录HKUST空调控制页面：`https://w5.ab.ust.hk/njggt/app`
2. 按 `F12` 打开开发者工具
3. 切换到 `Network` (网络) 标签
4. 刷新页面，找到任意一个 `ac-status` 或 `ac-balance` 请求
5. 在请求头中找到 `Authorization: Bearer xxxxxx`
6. 复制 `xxxxxx` 部分，这就是你的Token

### 4. 运行程序

```bash
python app.py
```

### 5. 访问界面

打开浏览器访问：`http://localhost:5000`

输入你的Token，点击"连接并获取状态"即可。

## 📝 API参考

### GET `/api/status`
获取空调状态（需要POST传递token）

**请求**:
```json
{
  "token": "your_bearer_token"
}
```

**响应**:
```json
{
  "device_name": "UG2-402",
  "is_on": true,
  "voltage": 228.1,
  "current": 3.788,
  "power": 0.8495,
  "power_factor": 0.9829,
  "kwh": 2052.23,
  "time": "2026-09-04 19:28:40"
}
```

### POST `/api/toggle`
切换空调状态

### POST `/api/schedule`
设置定时任务

```json
{
  "token": "your_token",
  "on_delay": 30,    // 30分钟后开启（分钟）
  "off_delay": 30,   // 30分钟后关闭（分钟）
  "is_loop": true    // 是否循环
}
```

### POST `/api/schedule/clear`
清除所有定时任务
